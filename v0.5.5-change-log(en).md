### Fix memory leaks, ESP32 SSL fallback, and add cleanup() API

## Bug fixes
---------
 - Fix ESP32 setInsecure() fallback in upgradeToSecuredConnection().
   When no CA cert / client cert / private key is configured on ESP32,
   WiFiClientSecure had no trust anchor and SSL handshake failed on most
   ESP32 core versions. Now mirrors the ESP8266 behavior: if nothing is
   configured, call setInsecure() on the underlying client.
 - Add SecuredEsp32TcpClient::setInsecure() (was missing entirely).
 - Guard setNoDelay(true) behind connect() success in GenericEspTcpClient.
   Previously setNoDelay was called unconditionally, which on a failed
   SSL handshake triggered "setSocketOption(): fail on 0, errno: 9,
   Bad file number" noise on ESP32 / ESP8266.

## Memory leak fix
---------------
 - Add WebsocketsClient::cleanup() (alias reset()) that releases the
   ~45 KB mbedtls context held by WiFiClientSecure on ESP32. Performs
   5 steps with null guards:
      1. If WS connection still open, send close frame + stop TCP/SSL
      2. _client.reset()   (drops WebsocketsClient's reference)
      3. Rebuild _endpoint with null socket   (drops endpoint's reference,
          finally triggering ~SecuredEsp32TcpClient -> ~WiFiClientSecure
          -> mbedtls context free, ~45 KB released)
      4. Clear _customHeaders
      5. Reset _sendMode to SendMode_Normal
   Idempotent and safe on moved-from instances.
 - connect(url) / connectSecure() now call cleanup() before reconnecting,
   so repeated connect()/close() cycles no longer accumulate stale
   WiFiClientSecure instances on the heap.
 - Destructor now unconditionally calls cleanup(), guaranteeing resource
   release even if the user forgets to call close().
 - Add null guards in WebsocketsEndpoint::poll / recv / send / close so
   post-cleanup calls return safely instead of dereferencing null.
 - Null-safe copy/move constructors and assignment operators (previously
   dereferenced other._client unconditionally and would crash on a
   moved-from or already-cleaned-up instance).

## ompatibility
-------------
 - Use WiFiServer::accept() on ESP32 core >= 3.x, fall back to
   WiFiServer::available() on 2.x, silencing the deprecation warning
   "NetworkClient NetworkServer::available() is deprecated: Renamed to
   accept()."
